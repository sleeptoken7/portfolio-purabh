# **Production-Grade Text-Based RAG System**

## **Detailed Technical Report**

---

# **1\. Introduction**

This project aimed to build a **production-oriented, text-based Retrieval-Augmented Generation (RAG) system** capable of:

* Parsing structured PDF documents (including grid-based tables)  
* Preserving layout integrity  
* Exporting parsed data before embedding  
* Performing semantic search using FAISS  
* Generating grounded answers using Mistral 7B  
* Providing a web-based chat interface with adjustable generation parameters

The system was designed to operate strictly in a **text-based pipeline (no OCR allowed)** and follow enterprise-level architectural principles.

---

# **2\. Initial Setup & Early Challenges**

The project began with a basic PDF → Text → Chunk → Embed → Query workflow in Jupyter Notebook.

### **Early Problems Encountered**

1. Import errors (Pillow `_imaging`, SciPy `_ccallback_c`)  
2. Llama BOS token duplication warning  
3. Poor answer quality  
4. Flat text extraction losing table structure  
5. Missing words during parsing  
6. Incorrect chunking splitting logical content  
7. Inability to preserve multi-column layout

Each issue required systematic debugging and architectural refinement.

---

# **3\. Improving LLM Integration**

Initially, prompt formatting caused duplicate BOS tokens in `llama-cpp`.

### **Solution:**

* Removed manual `<s>` tokens.  
* Switched to `create_chat_completion` API.  
* Structured system and user messages cleanly.  
* Reduced temperature for more deterministic output.

Result:

* Sharper, more grounded responses.  
* Reduced hallucination.

---

# **4\. Major Architectural Shift: Layout-Aware Parsing**

The biggest turning point was realizing the PDF was **grid-structured with multiple columns**.

Flat extraction using:

page.get\_text()

Destroyed column structure and lost semantic meaning.

---

## **4.1 Word-Level Extraction**

We switched to:

page.get\_text("words")

This provided:

* X/Y coordinates  
* Bounding boxes  
* Word-level granularity

This ensured **zero word loss**.

---

## **4.2 Grid Reconstruction Attempts**

We initially attempted:

* Line-based grid detection  
* Clustering vertical and horizontal lines

But discovered the PDF used **rectangle drawing objects (`'re'`)**, not simple lines.

---

## **4.3 Final Column Grid Detection Strategy**

We:

1. Extracted rectangle boundaries.  
2. Clustered all X positions.  
3. Detected stable vertical column boundaries.  
4. Reconstructed column zones.  
5. Assigned words to columns using X-coordinate ranges.

This allowed:

* Correct detection of 4 columns.  
* Handling merged cells.  
* Multi-page continuation support.  
* No hardcoding of column positions.

---

# **5\. Logical Record Consolidation**

The PDF had a critical structural challenge:

Descriptions spanned multiple visual rows.

Example:

| Chapter | Section | Title | Description |
| ----- | ----- | ----- | ----- |
| 1 | A | Intro | First line |
|  |  |  | Second line |
|  |  |  | Third line |

Without consolidation, each row was treated independently.

---

## **Solution**

We implemented a row consolidation engine:

* If Chapter/Section/Title are empty,  
* Append Description to previous record.

Result:

```json
{  
  "chapter": "1",  
  "section": "A",  
  "title": "Intro",  
  "description": "First line Second line Third line"  
}
```

This was a major upgrade in semantic integrity.

---

# **6\. Pre-Embedding Markdown Export (Teacher Requirement)**

The teacher required:

After parsing and before chunking, export parsed data to Markdown.

This was implemented as:

* Timestamped `.md` file generation  
* Includes:  
  * Document metadata  
  * Page 1 content  
  * Full structured table

This layer ensures:

* Transparency  
* Auditability  
* Debugging before embedding  
* Version control of ingestion

Pipeline became:

PDF  
 → Parse  
 → Consolidate  
 → Export Markdown  
 → Embed

This separation significantly improved architectural clarity.

---

# **7\. Embedding Architecture**

Instead of chunking arbitrary text, we embedded structured records:

Chapter: X  
Section: Y  
Title: Z  
Description: ...

Embeddings were generated using:

* SentenceTransformers (MiniLM)  
* Cosine normalization  
* FAISS IndexFlatIP

This improved retrieval precision significantly.
